DocsGPT＋Geminiの応答時間改善（2026-10-21）

構成の変更
改善前：日本語画面 → DocsGPT /api/answer（続きの質問のLLM言い換え、ベクトル検索、草稿生成） → チャンク全文取得 → Geminiで出典校閲・最終回答 → 機械照合。
改善後：日本語画面 → DocsGPT /api/search（ベクトル検索、チャンク全文） → Geminiで根拠原文付き回答の作成と意味の照合 → 同じ機械照合。
同じエージェントの12件の資料、同じgemini-3.5-flash-liteを使用。検索の埋め込みも既存DocsGPTのまま。
通常のGemini呼び出しを、初回2回・続き3回から1回に削減。検証に失敗した場合は従来どおり1回だけ修正を依頼する。
Geminiへ同じ回答を2回作らせる工程を減らし、検索と回答生成を分離した。検索語の制度名と直前の利用者の質問はコードで補う。制度が明記された新しい質問では過去の別制度を混ぜない。
回答キャッシュは使用していない。未検証の草稿を先行表示するストリーミングも使っていない。

残した出典検査
・事実説明には根拠原文を必須とする。引用は本文と照合する。
・制度名と、複数制度を扱うPDFの該当節を照合する。
・減免の説明には減免自体を記した原文が必要。
・確認項目や相談文に、制度事実の断定を紛れ込ませない。
・検証に失敗したら修正を依頼し、それでも不一致の説明は本文ごと除く。確認先・次の行動は残す。
・公式URLは既存の資料一覧から決める。生成されたURLをそのまま使わない。
・履歴のハッシュを照合し、表示済みの検証された回答だけを次の会話へ渡す。

今回の測定で追加した検査
・一時預かりの相談に、正しい出典が付いたショートステイの説明で答える「制度のすり替え」も拒否する。
・補助金・基準額の意味を出典のない補足へ分類した回答も拒否する。
これらは高速化前の検査より厳しい。改善前の実回答にも最終版の検査を再適用し、不一致を記録している。

測定方法
同じ2シナリオ、各6往復、合計12問を改善前後にそれぞれ実HTTPで実行。
ショートステイ：料金、全国一律か、9,210円/4,200円の意味、1泊2日の費用確認、明日利用の電話文、お礼。
一時預かり：仕事をしていない保護者の休息、保育という用語、料金の決め方、不明な金額の確認、産後ケアとの違い、電話文。
各条件で新しい会話を開始し、その条件の実回答を次の質問の履歴にする。質問列は同一だが、生成回答や検索結果のチャンクは同一とは限らない。
索引とサービスが起動済みの状態で計測。1問ずつ順次実行し、利用上限対策の18秒休止は計測時間に含めない。
回答完了までのHTTP時間を計測。upstreamMsは改善前にはDocsGPT内の検索・草稿までの合計、改善後には検索専用APIの時間。reviewMsはGeminiでの最終回答・出典確認・必要な再試行の合計。
DocsGPT内部の言い換え・草稿生成それぞれの秒数、Google内部のキュー・推論・ネットワークの内訳までは分離できていない。
1問1回の比較であり、統計的な性能保証ではない。改善前→改善後の順で測定しており、外部APIの混雑や出力差の影響もある。

予備計測について
performance-after-preliminary.jsonは予備4回答と1件の429を保持。
この429は自動会話テストと画面テストが重なり、アプリの同時実行制限に当たったもの。Geminiのレート上限ではない。
最終計測では操作を重ねず、新しい会話で12問を最初から実行。予備記録は統計から除外する。

保存と起動
npm startで改善版が標準。DOCSGPT_PIPELINE=legacy npm startで比較用の従来経路に戻せる。
DocsGPTの管理画面7093側の/api/answerは変更していない。4317の日本語画面が今回の対象。
検索語の記録はDocsGPTに残る。新しい経路ではDocsGPTの回答草稿・会話全文を作成しない。
Googleには会話と関連資料を送る。APIキーはサーバー内で読み、ブラウザーや検証結果へ返さない。
サーバー再起動後は「最初から」で新しい相談を開始する。

最終計測結果
回答完了までの中央値：5.16秒 → 2.94秒（43%短縮）。
平均：5.44秒 → 4.15秒。P90（nearest rank）：6.83秒 → 7.37秒。
最短：3.82秒 → 1.70秒。最長：7.58秒 → 12.78秒。
工程別の平均：DocsGPT内の検索・草稿まで 2.555秒 → 検索専用API 0.076秒。本文の追加取得 0.054秒 → 0.000秒。Gemini最終回答・出典確認 2.824秒 → 4.066秒。
改善後の最長12.78秒のうち12.64秒はGemini最終回答の呼び出し。再試行なしの1回でも遅い回があった。検索は0.14秒。この測定では典型的な時間と平均は短縮したが、P90・最悪時間は改善していない。Google側の待ち・生成・ネットワークのどれが原因かまでは判別できない。
改善後12回答の出典付き事実説明9箇所を最終検査で再照合し、原文・制度の不一致は0。使用した公式URL4件は全てHTTP200、取り込み原本のSHA256と一致。
改善前には一時預かりの相談へショートステイの事実で答えるケースが1件あり、最終の制度すり替え検査では拒否した。改善後の同質問は一時預かりの記載不足を限定して伝え、窓口への質問へつなげた。
修正を再依頼しても一部を落とした安全側の回答（partial）は改善前2件、改善後3件。根拠のない説明を無理に残さないための動作だが、回答の網羅性が常に同じとは言えない。
出典の原文一致・制度対応は確認できたが、自由生成の全表現の正確さを保証するものではない。お礼にも前の説明を繰り返す回があり、会話の簡潔さは今後の調整余地がある。
