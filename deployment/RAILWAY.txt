Railway配備手順・運用記録（2026-10-23）

対象
専用プロジェクト motto-kosodate-concierge。
公開URL: https://concierge-web-production-c372.up.railway.app
独自ドメイン予定: https://concierge.yasashii-sek.ai（DNS検証済み、証明書発行待ち）
既存mottoのプロジェクト・DB・Redisには変更しない。

構成
・concierge-web: Node 24、日本語相談画面。公開HTTPSはこのサービスのみ。
・concierge-docsgpt: arc53/docsgpt:1.0.0、APIとCelery workerを同じサービスで起動。非公開。
・Postgres / Redis: このプロジェクトで新規作成。既存mottoとは分離。
・両アプリに/data Volume。webの設定・管理キー・暗号化ログは/data/private内。
・検索モデルはIBM Granite multilingual r2。Ruriではない。
・公式資料12件をハッシュ照合後に新規投入。ローカルの相談ログやDBは移行しない。

配備
1. railway whoamiで認証を確認。新規プロジェクトを作り、環境・サービスを明示的にlinkする。
2. PostgresとRedisを新規作成。アプリに/data Volumeを作成する。
   CLI volume addはservice指定だけではpanicした。project/environment/serviceをrailway linkした後にvolume addすると成功した。
3. 環境変数を設定。秘密値はvariable set --stdinで送り、表示しない。
   DocsGPT: POSTGRES_URI、CELERY_BROKER_URL、CELERY_RESULT_BACKEND、CACHE_REDIS_URLを専用DB/Redisへ接続。
   API_URL/WORKER_API_URL=http://localhost:7091、PORT=7091、LLM_PROVIDER=google。
   PORTを省くとRailwayの起動チェックが別ポートへ向かうため、必ず7091を指定する。
   JWT_SECRET_KEY/ENCRYPTION_SECRET_KEY/INTERNAL_KEYは新規生成。
   TRACES_ENABLED=false/TRACES_CAPTURE_CONTENT=false。DocsGPTに公開ドメインを付けない。
   HOME=/home/appuser、HF_HOME=/data/models/huggingface、XDG_CACHE_HOME=/data/.cache。
   web: DOCSGPT_URL=http://concierge-docsgpt.railway.internal:7091、DOCSGPT_API_KEY、GEMINI_API_KEY、GEMINI_MODEL。
   APP_PUBLIC_ORIGINは公開HTTPSオリジンだけを指定。PORT=8080、HOST=0.0.0.0。
4. node deployment/prepare-contexts.mjsで許可リストに含まれるファイルだけを一時フォルダーへコピーする。
   APIキー、会話ログ、ローカル検証データは含めない。
   railway up <context> --path-as-root --project <id> --environment <id> --service <id> --detach
5. DocsGPT起動後、railway ssh経由でpython /opt/concierge/seed.pyを実行。
   /data/concierge-seed.jsonで再開可能。長時間SSHが切れてもアップロードを繰り返さない。
   索引完了後、キーは/data/concierge-agent.jsonへ保存。値をログに出さない。
6. エージェントキーをwebのDOCSGPT_API_KEYへ標準入力で設定。管理キーはcloudのVolumeで新規生成される。
7. ヘルスチェックをweb=/api/health（120秒）、DocsGPT=/api/health（300秒）に設定する。
   今回のCLIアップロードではrailway.tomlの起動判定設定が反映されなかった。
   environment editもNo changes to applyを返したため、公式API serviceInstanceUpdateで設定し読み返した。
   新規サービスでは旧Config as Codeを指定できないため、deployment/railway/railway.tsに現行IaCを保存。
   最新CLIのconfig pull→planでは変更なしを確認。変数はunmanagedで秘密値を記載しない。
   設定反映後、配備ログのStarting Healthcheckと成功を確認する。設定の読み返しだけで成功扱いにしない。
   公式API: https://backboard.railway.com/graphql/v2
   Python HTTPクライアントではUser-Agentを設定する。認証トークンを出力しない。
8. 最後に公開URLで会話、本文出典、同意なし非保存、同意あり保存、管理認証、再起動後永続化、取り消しを確認する。

クラウド固有の修正
・出典レビューが環境変数のAPIキーを使う前にローカルgemini-config.jsonを要求していた。
  GEMINI_API_KEY/GOOGLE_API_KEYがある場合はファイルを必須にしない。回帰テストを追加。
・非rootで動くDocsGPTにrootのHOMEを残さず、モデル・トークナイザーのキャッシュをVolumeへ向ける。

秘密情報・検証記録
プロジェクト/サービスID、配備状態、管理キー、接続キー、検証用同意トークンは.gitignore対象の.privateへ保存。
GitHub、配備用コンテキスト、公開報告には秘密情報や実在の会話ログを含めない。
管理画面は/admin。管理キーはチャットやURLに貼らない。
