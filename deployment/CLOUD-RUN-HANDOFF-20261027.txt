3. ユーザーが承認した費用制限
Cloud Run月500円のSpend capを設定済み。
API読み戻し：outputState=CONFIGURED、通貨JPY、金額500。
対象は「このプロジェクトのCloud Run全体」。検索コンテナ1個だけの上限ではない。
同じプロジェクトへ別アプリを置くと、それらも合算して月500円の停止基準を共有する。
別プロジェクトを作っても、この停止基準は自動では引き継がれない。
50% / 80% / 100%で通知。既存の月100円の通知専用予算も変更せず残している。

重要：
- Spend capは即時停止ではなく、超過分が請求される可能性がある。
- 計算は推定グロス費用基準で、無料クレジット等適用後の請求額とは一致しない。
- 翌月に自動リセットされる。
- Gemini API、Artifact Registry、DBなどはこのCloud Run上限の対象外。
- 通知だけのBudgetと、使用を止めるSpend capを混同しない。
- 金額や対象を無断で拡大しない。

4. 実機検証した構成（現在は削除済み）

5. 実測結果
制御された停止→自動起動の復帰3回：
- 最初の成功HTTP要求：5.67〜6.40秒。
- 手動停止解除の反映待ちを含めると最大12.76秒。
- 自然なアイドル停止からの復帰や長期p95は未測定。
- プロセスpeak RSS：約0.77GiB。2GiB構成で検証。コンテナ全体のピークとは区別する。

同じ12資料・gemini-3.5-flash-lite・出典検証コードで、各6往復×2シナリオを比較：
                              ローカルDocsGPT   Cloud Run検索
回答中央値                      2.93秒           4.37秒
検索フェーズ中央値               0.059秒          0.230秒
Cloud Runの回答待ちの大部分は、検索ではなくGemini＋出典検証だった。
引用27件（比較元11 / Cloud Run16）は原文に存在、公式URL5種類はHTTP200。
Cloud Run側の今回の回答に別制度リンクの取り違えは見つからなかった。
一方「ありがとう」に説明を繰り返す、硬い行政文体、過去の希望の一部を落とす問題が残る。
検索順位の完全一致は9/12、上位6本文の集合一致は11/12。精度が完全同一とは主張しない。
引用文字の一致・validator成功だけでは、意味の過剰一般化を防げない。
ホスト移行で会話品質まで解決したとは扱わない。

月1000質問を今回の長さ・再試行率で有料単価換算した目安：
- Cloud Run検索実行：無料枠が空いていれば0円見込み。
- イメージ保管：継続保管するなら約9円/月（約1.038GiB、無料枠0.5GiBが空いている場合）。
- Gemini：約$10.06/1000質問。
- 合計：約1600円/月＋通信・税・Web/API本体等。
Google Cloudカタログの1ドル157.195円換算による概算。実際の請求確定額ではない。
他アプリのCPU/RAM・起動頻度・DB・通信量には、そのまま適用しない。
