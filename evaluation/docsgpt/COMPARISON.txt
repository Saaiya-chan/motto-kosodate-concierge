DocsGPT 1.0.0 と現在の Ruri＋Gemini：ローカル比較
実施日 2026-10-21

結論
今回の2相談では、DocsGPTは会話の継続、お礼、料金の追質問への対応が良好だった。
現在のRuri＋Geminiは速いが、資料に答えがある質問でも回答を控える場面と、会話の主題を失う場面が残った。
ただしDocsGPTにも引用先の誤りが2回答あった。DocsGPTへの全面移行を、この結果だけで決めることは勧めない。
比較用DocsGPTは http://127.0.0.1:7093/ で稼働中。左側「motto比較・12資料＋Gemini」で試せる。
現在のsupport-finderの標準設定・アプリ処理は変更していない。

比較条件
・Geminiモデル名は両方 gemini-3.5-flash-lite。同じ保存済みAPIキー。
・元資料12件をSHA256照合。8PDFは元ファイル、4HTMLは現在のRuriが利用する保存済み本文TXTを取り込んだ。
・取り込み成功と、12ファイル全てに検索チャンクがあることを確認。
・DocsGPT 1.0.0 / commit 71ff06cb93baf34a1499e26a2875ee1d76bd0520
  image arc53/docsgpt@sha256:df854d647b08ad2d460f2529e7d63e626c0a1fd745eb6bfafb7d3bfe9efca5ef
・DocsGPT: classic agent / 6チャンク / Granite multilingual 311m r2 / FAISS / 79チャンク。
  標準の検索用質問書き換えを有効。会話履歴があればGeminiで質問を書き換えてから検索し、回答生成する。
  引用の標準テンプレートを保持し、日本語相談・資料根拠・不明時の次の行動を指定するプロンプトを追加。
・Ruri: 現在の標準構成そのまま / ruri-v3-70m / 296チャンク / 根拠の引用照合と必要時の修復。
・両者は同じモデル・元資料だが、抽出器、分割、検索、プロンプト、定型回答、生成設定は異なる。
  DocsGPTのthinkingは既定値、Ruriはlow。埋め込みモデルだけの優劣を測る実験ではない。
・昼間に預けて休みたい相談6往復、子育てショートステイ料金相談6往復。
  各方式は自分の過去の回答を履歴として使用。他方の回答は渡していない。
・送信から回答全文受信までのHTTP実測。最初の文字までの時間ではない。
  同時実行せず、交互の順序で実行。別質問の初回ウォームアップは集計外。
・毎分15回のGemini制限によるDocsGPT失敗が1回。間隔を空けて成功し、失敗・待機は正常応答時間から除外。
  失敗履歴はcomparison.json内attemptsに保存。再試行した1回答は検索用質問のキャッシュが効いた可能性がある。
・各質問1回の少数例。一般的な正答率や安定した速度差を保証する結果ではない。

会話の確認結果
昼間相談1: 就労していなくても休息のため一時預かりを相談できるか
  両者とも資料付きで回答。DocsGPTは長めでショートステイも列挙。
昼間相談2: 「保育を受けること」って何？
  Ruriは「子どもを預かって、世話をしてもらうこと」と平易。
  DocsGPTは制度定義の再説明が中心で、用語の言い換えとしては硬い。
昼間相談3: 仕事をしていなくても休むために預けていいか
  両者とも育児負担軽減を根拠に回答。
昼間相談4: 料金をどう確認するか
  Ruriは具体額不明の範囲を限定し、問い合わせ先の探し方・確認項目を案内。
  DocsGPTも案内したが、一時預かりの料金説明に短期支援事業のFAQを引用した。
昼間相談5: 電話で言う相談文
  両者とも2歳・休息目的を引き継いだ例文を作れた。
昼間相談6: 「ありがとう。まず聞いてみます。」
  DocsGPTは自然な締め。Ruriは「確認できる記載が見つからない」と返し、不要な手続き案内を繰り返した。

短期相談1: 子育てショートステイのお金
  Ruriは利用料が市町村設定であることに絞り、追加費用・総額等の確認を提案。
  DocsGPTは同じ結論に加え、利用者に必要性の低い運営費・加算額の説明も出した。
短期相談2: 全国同じ料金か
  DocsGPTは市町村ごとに設定と回答。Ruriは根拠判定で却下し、答えを出せなかった。
短期相談3: 1泊2日で確認するお金
  Ruriは総額・食費等の追加費用・減免を具体的な確認項目として提示。
  DocsGPTは「利用料を確認」とだけ答え、具体性が乏しい。
短期相談4: 9,210円・4,200円は自分が払うお金か
  DocsGPTは運営費・補助基準の額で、本人負担額そのものではないと区別した。
  Ruriは具体料金不明の案内に流れ、質問の核心を説明できなかった。
短期相談5: 明日使えるかも問い合わせる文
  DocsGPTはショートステイ・1泊2日・明日利用・料金・減免を含む文を作成。
  ただし末尾の料金設定説明に産後ケア等の不適切な引用が付いた。
  また冒頭を「明日すぐに問い合わせ」と書き、明日利用したい意図とのずれがある。
  Ruriは「利用したい支援」という汎用文になり、ショートステイ・明日利用の文脈を失った。
短期相談6: 「ありがとう。市に相談してみるね。」
  DocsGPTは自然な締め。Ruriは資料不明の返答に戻り、養育支援訪問事業へ話題がずれた。

出典の確認
引用番号の存在だけでなく、引用キーに対応するチャンク全文を取り出して照合した。
DocsGPT: 引用のある9回答のうち、2回答に明確な対応不良。
  A4: 一時預かりの料金設定 → 子育て短期支援事業FAQ問14。
  B5: 子育てショートステイの料金・利用可否 → 産後ケアの設備等の記述[4]と短期支援要綱末尾[6]。
      料金設定の根拠となる問14を引用していない。
  その他7回答は主要な制度説明に対応する根拠を確認。
  引用チャンクへの参照は全件解決できた。リンク切れがなくても、内容の取り違えは起きる。
Ruri: 出典付き回答は4/12。5つの制度説明の引用原文を全て登録チャンクに照合し、対応を確認。
  残り8回答は提案・定型文・回答不能の案内等で、これを正答や出典の正確さに加点しない。
  答えを控えることで誤引用は少ないが、答えられる質問まで控えていることが利用上の問題。
上記は今回の回答単位の目視確認であり、厳密な全主張の正答率・引用網羅率ではない。

運用上の結果と判断
・DocsGPTは管理画面、資料登録、会話保存、引用表示までローカルで動作した。
・backend / worker / PostgreSQL / Redisを専用Composeで起動。外向き公開はせず127.0.0.1:7093のみ。
・初回backend/workerの同時DB初期化が競合しbackendが停止。workerの初期化後にbackendを再起動して解消。
・12件の初回取り込みは約106秒（モデル初回準備を含む）。PDF1件はOCR判定後に通常PDF抽出へフォールバック。
  全ページの文字認識完全性までは監査していない。12ファイルのチャンク生成は確認済み。
・比較後のDockerメモリはworker約1.28GiB、backend約0.47GiB（DB/Redis等は別）。
・Gemini推論はクラウド。検索・資料保存・画面がローカルでも、質問・検索結果は回答生成のためGeminiへ渡る。
・会話の自然さにはDocsGPTを使う価値がある。速度は現在のRuriが優勢。
・子育て相談の標準にするには、DocsGPT側にも制度ごとの検索絞り込み、料金と補助金の分離、引用内容の検証が必要。
・現行Ruri側も主題の引き継ぎ、お礼判定、料金質問の過剰な回答抑止を改善する余地が確認できた。
