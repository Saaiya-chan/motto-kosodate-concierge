結論
Cloud Runは、今の検索方式を維持しながら常時稼働のサーバー料金を減らす候補になる。
東京の実機で検索は約0.23秒、Gemini込みの回答中央値は4.37秒。
停止復帰は最初の成功HTTP要求5.67〜6.40秒。手動停止解除の反映待ちを含むと最大12.76秒。
今回の範囲で、Cloud Run側の引用16件に別制度の資料への誤対応は見つからなかった。
一方、会話の繰り返しや硬い制度文、説明不足は残り、公開版の品質合格とはしない。
本番・DNSの切り替えは行わず、検証用Cloud Runと専用保管庫を削除した。

会話の確認
良かった点：
- ショートステイで「明日から1泊2日」を引き継ぎ、窓口に伝える文を生成。
- 日中の相談で一時預かりとこども誰でも通園を両方紹介し、未就園の回答を引き継いだ。
- Cloud Run側は制度比較で保護者の必要性とこどもの育ち、事業と給付制度の違いを引用付きで説明。
- 一時預かりの具体的な料金が不足する場合、自治体・施設への質問文まで案内。

残る問題：
- 両方式とも「ありがとう」に制度説明や窓口文を繰り返した。
- Cloud Runの利用期間は行政資料の文体のままで、相談への返事として硬い。
- Cloud Runで利用者に「お住まいの地域ではどのような預け方が可能か」と問い返す不自然な文。
- Cloud Runの電話文は「明日1泊2日」は引き継いだが、以前の料金・減免の相談を落とした。
- ローカル側の制度比較は一時預かりだけになり、誰でも通園との比較が欠けた。
- 用語の言い換え「お子さんを保育所などに預かって」は「預けて」のほうが自然。
これらをホスト移行による改善や品質合格とは扱わない。

出典の確認
両方式合計27引用（ローカル11 / Cloud Run16）はすべて登録原文に存在。
公式リンク5種類はすべてHTTP200（PDF4 / HTML1）。
Cloud Run側の利用料はショートステイFAQ、利用期間は同実施要綱、
一時預かりは該当基礎資料の節、誰でも通園は専用公式サイト・ハンドブックに対応。
この12回答で、Cloud Run側に別制度へのリンク取り違えは観測しなかった。
それでも引用の文字一致とvalidator成功だけで意味の正確さを保証できない。
今回ローカル側の減免回答は「所得に応じた」としたが、引用は児童希望・ひとり親等の免除/減免。
所得に応じるという主張をその引用から直接導けず、validatorが通っても意味の過剰一般化が残った。
Cloud Run側の対応回答は原文の減免対象を具体的に挙げていた。
Cloud Runの日中相談にある「ご利用いただけます」は地域での利用確定と読めるため、
候補であること・地域で確認が必要であることをもっと明確にすべき。
会話品質・出典精度の本番保証や、資料外の質問全般を評価したものではない。
