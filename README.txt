motto 子育て支援ナビ（このMacで動く試作）

使う
このMacでは start.command をダブルクリックして起動できます。
1. このフォルダで npm start を実行します。
2. http://127.0.0.1:4317 をブラウザで開きます。
標準はRuri検索＋Geminiです。設定画面でGemini APIキーを保存してください。
Ruriとキーワード検索はこのMacで実行し、関連本文と会話をGoogleに送信して回答します。
File Searchへの資料登録は比較用で、標準モードでは不要です。
Node.js 22以上と、準備済みの .venv-ruri／モデルキャッシュを使用します。
「このMacのAI」を選ぶ場合だけOllamaと qwen3:4b が必要です。

出典付き回答
主回答と補足を一文ずつ生成し、各文の出典IDと8文字以上の原文引用を取得します。
直前の説明への聞き返しは、その文脈を使い、引用付きでやさしく言い換えます。
単独のお礼・相づち・挨拶は資料検索を使わず応答します。
取得した資料内にIDと引用が実在するか照合し、不明なID・出典なしの文・一致しない引用を拒否します。
文末の番号から公式資料へ移動でき、「この回答の根拠を読む」で該当原文を確認できます。
資料に答えがない場合は、何を確認できないかを示し、確認項目・公式案内の探し方・相談文を提案します。
制度の事実と「次にできること（確認の提案）」は別に表示し、提案に架空の料金・窓口URL・利用資格を追加しません。
申込手順が取得本文にない場合は、預かり場所を申込先と取り違えて説明しません。
引用が照合できないモデル回答は破棄し、制度を断定せず確認の提案を返します。
原文との一致は機械照合しますが、言い換えの意味が根拠に沿うかを完全に保証するものではありません。

できること
・自由文や選択肢で困りごとを入力し、追加質問から候補を絞る。
・全国共通の11制度から最大3件を提案。理由、違い、確認点、公式リンク、情報確認日を表示。
・相談窓口に伝える文を生成してコピー。
・年齢や通園状況を答えずに進むことも可能。
・回答モードを明示し、APIエラー時に別のAIへ自動で切り替えない。選択式はローカルモードで利用可能。

構造
public/ : ブラウザ画面。外部CDN・解析サービスを使わない。
src/server.mjs : 127.0.0.1専用HTTPサーバー。Host/Originの確認、入力上限、同時生成制限。
src/llm.mjs : ローカルOllama/Qwen3 4Bによる、ユーザー発言の根拠付き困りごと抽出。
src/engine.mjs : 日本語2文字単位の検索、条件フィルター、スコア、追加質問、根拠表示。
data/programs.json : 国の公式情報から編集した制度ごとの概要・条件・確認事項・出典。

RAGと会話回答
国の公式PDF・Web本文12件を data/documents/ に保存し、296個の本文抜粋をローカル検索します。
PDFの物理ページ番号、公式URL、取り込み日、ファイルのSHA-256は source-manifest.json／source-chunks.json に保持。
制度名で資料を絞り、質問内容の日本語2文字検索と用語の補完で関連箇所を取得します。
Qwen3 4Bには会話と検索した本文抜粋を渡し、最新の質問への回答と参照箇所IDを生成させます。
ページをまたぐ文脈を補い、引用符内の語句を本文と照合します。存在しない出典IDは拒否し、回答の下に資料名・PDFページ・原文抜粋を表示します。
『どんな事業？』『それはいくら？』『料理や掃除はどこまで？』などの聞き返しを処理します。
資料にない金額・地域条件・利用可否は、確認できないと伝えるよう指示しています。
制度候補の絞り込みには、編集済みの programs.json と明示された年齢・通園条件を併用します。
原文に基づく生成でも誤読や出典との不一致が完全に防げるわけではありません。表示された原文を確認できます。
ローカルモードではベクトルDB・埋め込み・外部APIは利用していません。質問時に公式サイトへアクセスしません。
AIが使えない場合は、編集済み制度データに基づく定型説明へ切り替えて明示します。

資料の更新（保守作業）
python3 scripts/ingest-sources.py
このコマンドだけが公式サイトから資料を取得します。pdftotextが必要です。
取得内容を確認し、npm testを実行してからサーバーを再起動してください。

情報と限界
確認日：2026年10月20日。国の制度の概要が対象です。
自治体情報・空き・地域料金・個別の利用可否・予約・申請は未実装です。
対象要件の例外や個別の事情は窓口で確認してください。制度データは自動更新されません。
医学的診断・緊急対応の代わりになるシステムではありません。
多人数が同時に使う公開サービス向けの負荷試験はしていません。

相談内容の扱い
ローカルモードはローカルモデルのみ使用し、:cloudモデルとOllamaのremote_model／remote_host付きモデルは拒否します。推論リクエストのリダイレクトにも追従しません。会話や相談プロフィールをサーバーのファイルやDBに保存しません。
画面の会話はブラウザのメモリーにのみ保持し、最初から／再読み込み／タブを閉じると消えます。
モデル取得時はOllamaの配布元へ接続します。ローカルモードの相談時のサーバー接続先はローカルOllamaのみです。
公式リンクを開いたときはそのWebサイトに移動します。
Ollama本体のログ設定や他アプリによる利用は、このアプリの管理対象外です。

後で自治体情報を追加する場所
programs.jsonのnational IDを安定したキーとして保持し、local-offers.json等に自治体コード、programId、地域条件、料金、窓口、出典、更新日を別レコードで追加します。
全国候補の提案の後、利用者が地域の案内を希望した段階で市区町村を聞き、そのIDで地域情報を結合する想定です。
全国情報を自治体ごとに複製しないため、今回のデータや条件判定を再利用できます。

検証
npm test : 条件の境界、否定、複数児、訂正、偽のLLM根拠、プロンプト注入等のテスト。
npm run test:conversation : ローカルAIで制度説明、料金、支援範囲、資料にない地域情報の連続質問を検証。
npm run test:llm : 起動中のサーバーとローカルモデルを使った架空の相談5例。test/llm-verification.jsonに結果。

Gemini File Search（2026年10月21日に実APIで接続確認）
・画面の「Geminiの設定」からAPIキーを登録し、「公式資料11件をGoogleに登録して準備する」を押します。
・キー作成先：https://aistudio.google.com/apikey
・有効な請求先を紐付けたGoogleプロジェクトのキーを使ってください。
・保存時は形式のみ確認します。有効性・モデル利用権限は資料準備時のGoogle API呼び出しで確認します。
・資料が11件すべて利用可能になったことをGoogle側で確認した後、回答モードでGeminiを選べます。
・比較には架空の相談を使用してください。Geminiモードの会話はGoogleへ送信され、資料の索引作成と回答生成に料金がかかります。
・ローカルとGeminiの会話は別々にメモリーで保持します。モードの切り替えでは互いの会話を送信しません。
・Geminiの回答はGoogleが返した参照情報を取り込み済みの公式資料IDに照合し、資料名・ページ・本文抜粋を画面に表示します。
・Google APIの接続先は generativelanguage.googleapis.com に固定。ブラウザにAPIキーを返しません。
・キーは .private/gemini-config.json（権限600）、資料取り込み状態は .private/gemini-state.json に保存します。.private/ はGitの対象外です。
・環境変数GEMINI_API_KEY／GOOGLE_API_KEY／GEMINI_MODELでも設定できます。環境変数はローカル設定より優先します。
・標準モデルは公式File Search例で使われている gemini-3.8-flash。アカウントで未対応なら設定欄のモデル名を変更します。
・アップロード中断時は保存済みの操作IDから再開します。資料ファイルを更新した場合は古い索引と混在させず停止します。
・公式資料11件のGoogleへの取り込みと検索準備が完了。Gemini 3.6 Flashで架空の相談・制度説明・料金の追質問・資料範囲外の応答を実APIで確認。3.8 Flashは一度回答後にタイムアウトと503が発生したため、保存済み設定を3.6 Flashに変更しています。
・node scripts/check-gemini.mjs でGemini単独の4ターンを検証し、test/gemini-live-conversation.json に回答と出典を記録します。このスクリプトは架空の相談だけを保存します。費用の請求額は未確認です。
・npm test のHTTPサーバーは専用の一時設定フォルダを使い、保存済みの実APIキーを読みません。MOTTO_GEMINI_PRIVATE_DIRで設定フォルダを指定できます。
・資料準備後は npm run compare:providers で、同じ架空相談4ターンの回答・出典・所要時間・トークン使用量を test/provider-comparison.json に記録します。未準備なら実行せず停止します。
・既存のローカルモードは継続利用できます。Googleの料金や利用枠エラーをローカルAIの回答として隠しません。

Ruri検索＋Gemini（比較用）
・モデル：cl-nagoya/ruri-v3-70m、固定revision 07a8b0aba47d29d2ca21f89b915c1efe2c23d1cc。
・.venv-ruri/ に専用Python環境、.cache/ にモデルと索引を保存。通常の検索はHF_HUB_OFFLINEで動作し、質問をHugging Faceへ送りません。
・検索文書には「検索文書: 」、質問には「検索クエリ: 」を付けて正規化ベクトルの内積で検索します。質問用モデルはCPUで常駐します。
・初回索引作成は287チャンクを対象とし、原文のハッシュとモデルrevisionで更新を検出します。最長入力が設定2048トークンを超える場合は切り詰めず停止します。
・制度名の文脈補完とキーワード検索2枠を併用し、意味検索だけで落ちた料金等の根拠を補います。取得する本文は最大6件です。
・Gemini File Searchツールは呼ばず、取得本文と会話をGeminiへ渡します。現在と同じ保存済みGeminiモデルを使います。
・Geminiが返した本文IDを実際の取得本文と照合して公式URL・ページを表示。架空の出典、本文にない引用、生成されたURLを拒否します。内容の正しさを機械的に保証するものではありません。
・画面の回答モードで「Ruri検索＋Gemini」を選べます。Ruri検索時間とGoogle回答生成時間を分けて表示します。
・npm start / start.command はRuriを先に読み込みます。通常起動時の読み込みと初回索引作成は、比較の通常応答時間から分けて報告します。
・新しい環境では python3 -m venv .venv-ruri と .venv-ruri/bin/python -m pip install -r scripts/ruri-requirements.txt で依存関係を準備し、 .venv-ruri/bin/python scripts/ruri-worker.py < /dev/null を一度実行してモデルと索引を準備します。
・node scripts/check-ruri-retrieval.mjs はGoogleを使わずに検索の根拠5項目を照合します。
・npm run compare:ruri はFile SearchとRuri構成を交互の順番で比較し、test/ruri-comparison.jsonに架空の質問・回答・出典・時間・使用トークンを保存します。429時は停止します。
・比較は同じ元資料・同じGeminiモデルを使いますが、チャンク分割、絞り込み、回答の出典形式は構成ごとに異なります。Ruriのモデル単体の優劣を測る試験ではありません。
